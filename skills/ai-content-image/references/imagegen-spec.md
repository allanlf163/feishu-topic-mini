# AI 生图完整规范

这份文档是本 skill 的核心执行规范。凡是最终图片生成，都必须遵守这里的规则。

## 1. 核心规则

最终图片只允许使用 `image_gen` 生成。

不允许把下面这些方式作为最终成图路径：

- HTML/CSS 页面截图。
- SVG、canvas、PIL、Chart.js 或其他代码绘图。
- 模板引擎生成海报。
- PPT/Keynote/浏览器截图充当最终图。
- 先 AI 出图再用代码改字、补字、擦字。

允许使用代码或文档做这些辅助工作：

- 保存 prompt。
- 保存规划、QA 记录和生成记录。
- 整理文章内容。
- 检查文件结构。
- 写长期记忆。

如果当前环境没有 `image_gen`，必须停止并说明：这个 skill 是 AI 生图流程，不能切换到代码成图替代。

## 2. 生成前必须判断的信息

每次生成前必须判断：

- 平台：公众号、小红书、通用文章，或其他。
- 图片类型：头图、封面、正文插图、知识卡、轮播页、概念图、流程图。
- 使用位置：文章顶部、正文某段后、小红书第几页、课程讲义封面等。
- 目标读者：新手、学员、客户、私域用户、公众号读者、小红书用户。
- 图片目的：吸引点击、解释概念、总结步骤、呈现对比、建立情绪、展示产品。
- 输出数量：单张还是多张。
- 比例和尺寸。
- 是否需要可见文字。
- 是否使用长期偏好或自定义风格。

如果这些信息缺失但可以合理推断，就直接推断；如果会影响比例、平台或数量，就问一个简短问题。

## 3. 文章内容拆解规范

用户给出文章、草稿、课程内容或长段资料时，先拆内容，再写 prompt。

必须拆出：

- 核心主题：这篇内容到底讲什么。
- 目标读者：谁需要这张图。
- 读者问题：读者为什么会关心。
- 主结论：最重要的一句话。
- 知识点：可以变成模块、清单、流程或对比的内容。
- 行动点：读者看完后可以怎么做。
- 避坑点：读者容易做错什么。
- 例外和边界：什么时候不适用。

拆图原则：

- 一张图只承担一个主要任务。
- 封面负责吸引和承诺。
- 内容页负责讲清一个知识点或行动步骤。
- 正文插图负责帮读者理解一段内容。
- 不要把文章按自然段机械变成图片。
- 不要为了凑页数制造空图。
- 不要为了少出图而删除关键判断和行动信息。

规划时可以把每张图标成：

- `吸引型`：封面、标题图、开篇图。
- `解释型`：概念、关系、机制。
- `步骤型`：流程、SOP、清单。
- `对比型`：正确/错误、前后变化、A/B 方案。
- `总结型`：结论、行动提醒、复盘表。

## 4. 默认目录和记录

如果能写文件，建议保留生成记录。

单图任务：

```text
img/
  prompt.md
  qa.md
  manifest.json
  <图片文件名>.png
```

多图任务：

```text
runs/<run-id>/
  source.md
  analysis.md
  outline.md
  prompts/
    01-cover.md
    02-page.md
  qa.md
  manifest.json
  images/
    xhs-01-cover.png
    xhs-02-page.png
```

如果没有明确文章路径或输出目录，可以只在对话里保留规划和 prompt，不强行写文件。

## 5. 生成记录 manifest 建议字段

`manifest.json` 不是给普通学员看的，但有助于复盘。建议包含：

- `schema_version`
- `run_id`
- `created_at`
- `route`
- `platform`
- `output_dir`
- `params.model`
- `params.aspect_ratio`
- `params.target_size`
- `params.count`
- `style.name`
- `style.lock`
- `images[].filename`
- `images[].prompt_path`
- `images[].version`
- `images[].status`
- `images[].qa_path`
- `images[].shown_to_user`

如果只是轻量使用，可以不强制写完整 JSON，但 prompt 和 QA 结论要能追溯。

## 6. Prompt 必备结构

每个最终 prompt 都应包含：

1. 任务入口：如 `/公众号配图`、`/小红书配图`、`/笔记本风格`。
2. 平台和用途：比如“公众号长文头图”“小红书第 2 页方法卡”。
3. 比例和尺寸：比如 `21:9, 2100x900` 或 `3:4, 1080x1440`。
4. 目标读者：谁会看这张图。
5. 图片要解决的问题：吸引点击、解释关系、总结步骤、强化记忆等。
6. 可见文字：标题、标签、步骤、注释、底部提醒。
7. 画面结构：主视觉、模块、箭头、卡片、对比栏、流程节点。
8. 视觉风格：平台感、材质、字体气质、色彩、光线、构图。
9. 风格锁：多图任务必须写。
10. 文字策略：文字多还是少，是否手写，是否需要短句。
11. 负向约束：不要什么。
12. 版本号：如 `v1`、`v2`。

## 7. Prompt 模板

可以按这个结构写：

```text
任务：/小红书配图 笔记本风格
平台：小红书
用途：第 1 页封面
尺寸：3:4 竖图，1080x1440
读者：想学习内容运营的新手学员
图片目标：让读者一眼知道这是一组可收藏的方法笔记

画面文字：
- 主标题：3 步做出可收藏笔记
- 副标题：选题 -> 结构 -> 发布检查
- 标签：新手友好 / 可直接套用 / 少走弯路

视觉风格：
真实螺旋笔记本页面，暖白纸张，桌面轻微阴影，黑色手写中文，红色圈重点，淡黄色荧光笔标签，手绘箭头和方框。

构图：
顶部大标题，中间三步流程，底部一个检查清单。留出安全边距，信息密度中等偏高但清晰。

风格锁：
全组使用同一种笔记本纸张、同一种黑色手写笔迹、红色重点和黄色高亮，后续页面延续同样模块样式。

文字策略：
所有中文短句清晰可读，不写长段落，不出现乱码，不把正文挤成小字。

负向约束：
不要 PPT 风，不要扁平模板，不要广告海报，不要随机人物，不要 logo，不要水印，不要密密麻麻的长段文字。

版本：v1
```

## 8. 文案优先原则

AI 生图不是先写“好看图片”再随便加字，而是先确定图片要表达什么。

默认要规划：

- 主标题。
- 副标题或一句解释。
- 模块标题。
- 步骤名。
- 标签、callout 或注释。
- 必要的底部提醒。

只有用户明确要纯图、背景图、氛围图、产品场景图，或者文字会破坏用途时，才生成无字图。

## 9. 中文文字策略

为了减少中文乱码：

- 不要求模型渲染长段落。
- 用短标题、短标签、短句。
- 每条可见文字尽量控制在一行。
- 重要专有名词单独放大，不要塞进长句。
- 内容页用模块、清单、流程节点承载信息。
- 如果文字很多，拆成多张图，不要强行塞进一张。
- 如果出图文字乱码，减少文字、放大字号、重写 prompt 后重生成。

不要用代码修复 AI 图里的文字。

## 10. 文字预算和密度判断

不同平台文字密度不同：

- 公众号头图：低文字密度，只放短标题和可选副标题。
- 公众号正文图：中低文字密度，标题加 2-5 个标签或节点。
- 小红书封面：标题要强，信息流缩略图可读。
- 小红书内容页：可以中高密度，但必须分层清晰。
- 笔记本风格：可以中高密度，但必须像真实笔记，不能像小字堆满的打印纸。

图片太空和图片太挤都算失败。判断标准是：读者能不能在手机上快速看懂重点。

建议文字预算：

- 公众号头图：1 个主标题，最多 1 个副标题；总文字尽量少。
- 公众号正文图：1 个短标题，2-5 个标签或节点。
- 小红书封面：1 个强标题，1 个副标题或 2-4 个短标签。
- 小红书内容页：1 个页面标题，3-6 个模块或清单项；每个模块最好有短解释。
- 笔记本风格内容页：可以信息更密，但必须模块化，不能像打印出来的小字讲义。

这不是硬性字数限制。判断标准始终是：手机上是否能读懂、是否有层级、是否服务图片目标。

## 11. 风格锁

同一篇文章或同一组图，必须建立风格锁。

风格锁至少包含：

- 字体或笔迹类型：宋体感、黑体感、手写笔记感等。
- 标题层级：封面标题、内容页标题、模块标题。
- 标签样式：圆角标签、手绘框、荧光笔、气泡、便签等。
- 色彩系统：主色、强调色、背景色。
- 构图语言：卡片式、笔记本、白板、杂志头图、流程图。
- 材质：纸张、屏幕、白板、照片、插画、真实桌面等。

后续每张图 prompt 都要明确“延续同一风格锁”。如果后续图突然换字体、换色彩、换构图，应视为失败并重生成。

## 12. 品牌一致性

如果用户提供品牌信息，优先纳入风格锁：

- 品牌色。
- 辅助色。
- 字体气质。
- 常用视觉元素。
- 不希望出现的元素。
- 账号调性：专业、温和、犀利、陪伴感、课程感等。

没有品牌信息时，不要假设用户有固定品牌规范。可以用平台默认风格先生成，并在任务结束后把稳定偏好写入 `memory.md`。

不要把品牌 logo、商标或官方认证标识画进图里，除非用户明确提供并说明可以使用。即使可以使用，也要避免让图片看起来像官方背书或平台认证。

## 13. 参考图和参考链接

用户提供参考图时，只把它当作：

- 风格参考。
- 构图参考。
- 材质参考。
- 色彩参考。
- 物体外观参考。

不要默认复刻受版权保护的图，也不要承诺像素级一致。

如果用户明确说明图片归自己所有，可以更强地保持品牌、产品或人物一致性，但仍要避免冒充真实未发生的场景。

## 14. 真实性和隐私边界

AI 配图可以表达观点、方法、场景和结构，但不能制造让读者误以为真实发生的证据。

避免生成：

- 假聊天记录。
- 假转账截图。
- 假后台数据。
- 假平台通知。
- 假媒体报道。
- 假证书、假奖项、假认证。
- 真实人物未授权背书。
- 与真实品牌、平台、机构混淆的视觉。

如果需要表现这些主题，使用抽象化表达：

- 用“示意图”“流程图”“风险提醒”“案例结构”。
- 用虚构且明显非真实的数据。
- 不出现可误导的真实 UI、真实公章、真实证件样式。

隐私规则：

- 不把用户私密资料、客户信息、手机号、微信号、订单号、身份证号写进 prompt。
- 截图或聊天记录中的敏感信息应先脱敏再作为内容来源。
- 长期记忆里不存私人身份信息和客户资料。

## 15. 生成前确认门

以下任务必须先给规划：

- 公众号文章头图和正文图。
- 小红书轮播图。
- 多张系列图。
- 文章转卡片。
- 笔记本风格干货图。
- 含较多中文文字的图片。

规划中必须出现：

- 每张图的用途。
- 每张图的可见文字。
- 视觉结构。
- 尺寸。
- 风格说明。

用户确认后再调用 `image_gen`。

## 16. 出图前 prompt 自检

调用 `image_gen` 前，快速检查 prompt 是否满足：

- 平台、用途、比例、尺寸写清楚。
- 画面文字是具体短句，不是“加一些文字”。
- 构图写清楚，有主次关系。
- 风格不是空泛词，比如只写“高级感”。
- 多图任务有风格锁。
- 中文文字没有太长段落。
- 负向约束没有列出可能泄漏到画面的敏感词。
- 没有要求生成假截图、假认证、假数据。
- 没有把网络搜图或下载作为步骤。

如果 prompt 没过自检，先改 prompt，再生成。

## 17. 失败重试策略

可修复失败包括：

- 比例不对。
- 中文乱码。
- 文字太小。
- 图太空。
- 图太挤。
- 风格漂移。
- 平台感不对。
- 出现无关元素。
- 没有表达核心信息。

处理方式：

1. 记录失败点。
2. 判断原因：文字太多、约束太弱、风格描述太泛、比例没有写死等。
3. 改 prompt。
4. 重新生成。

同一张图最多重试两次。两次后仍失败，停止并告诉用户下一版应该怎么改。

## 18. 安全和敏感表达

涉及投诉、侵权、付款、诈骗、法律风险、平台处罚等主题时，图片文字要用中性、教育性表达。

推荐表达：

- 风险套路。
- 先别付款。
- 先留证据。
- 核对身份。
- 处理流程。
- 平台通知。

避免在 prompt 里反复列出高风险词，尤其不要把禁止词写进负向约束，因为模型可能把这些词画进图里。

如果需要记录精确风险词，写在分析或 QA 里，不放进最终生图 prompt。

## 19. 展示结果

成功图片：

- 直接在对话中展示。
- 简短说明图片用途。
- 如有轻微问题，说明是否建议重生成。

失败图片：

- 默认不展示。
- 用户要求时再展示。
- 说明失败原因和下一版方向。
