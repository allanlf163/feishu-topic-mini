# 出图 QA 检查清单

生成图片后，必须先检查，再展示给用户。检查的目的不是追求完美，而是避免明显不能用的图被当成成品交付。

## 1. 通用检查

每张图都要看：

- 平台是否正确。
- 比例是否正确。
- 图片用途是否明确。
- 画面是否和内容相关。
- 主视觉是否清楚。
- 标题是否可读。
- 层级是否清楚。
- 文字是否乱码。
- 是否有无关物体。
- 是否有 logo、水印、奇怪 UI。
- 是否有明显畸形的人手、人脸或物体。
- 裁切是否正常。
- 四周是否有安全边距。
- 是否符合用户长期偏好。

## 2. 文字检查

检查：

- 中文标题是否大致正确。
- 关键字是否可读。
- 字号是否太小。
- 是否出现乱字、错字、糊字。
- 是否把长段文字挤进图里。
- 标题、标签、正文是否有层级。

如果失败：

- 减少文字。
- 放大关键文字。
- 拆成更多图。
- 把长句改成短句。
- 把专有名词单独放大。
- 重新生成。

不要用代码修图里的字。

## 3. 公众号检查

头图：

- 是否是 21:9 横图。
- 是否有标题安全区。
- 是否像公众号长文头图。
- 是否成熟、克制、可信。
- 是否避免了廉价营销海报感。
- 标题是否短而清楚。
- 是否没有塞正文段落。

正文插图：

- 是否是 16:9。
- 是否能解释一个概念、关系、流程或对比。
- 是否有 2-5 个有用标签。
- 是否比纯装饰图更有理解价值。
- 是否与文章段落对应。

多张公众号图：

- 字体气质是否一致。
- 标签样式是否一致。
- 色彩是否一致。
- 风格是否没有突然漂移。

## 4. 小红书检查

每张图：

- 是否是 3:4 竖图。
- 是否接近 1080x1440。
- 是否像小红书图文，而不是公众号横图或 PPT。
- 标题是否手机缩略图可读。
- 信息是否有收藏价值。
- 页面是否既不太空也不太挤。

封面：

- 是否有强 hook。
- 是否一眼知道主题。
- 是否有明确视觉焦点。
- 是否能让人停下来。

内容页：

- 是否一页一个核心点。
- 是否有模块、标签、步骤或对比。
- 是否有短句解释。
- 是否没有长段原文。
- 信息密度是否合理。

多页：

- 页数是否符合内容深度。
- 是否没有为了压缩页数丢掉重要信息。
- 风格是否统一。

## 5. 笔记本风格检查

必须看起来像：

- 真实笔记本或螺旋笔记本。
- 暖白纸张。
- 手写中文。
- 红色重点。
- 黄色高亮。
- 手绘方框和箭头。
- 结构化学习笔记。

失败情况：

- 像 PPT。
- 像扁平海报。
- 只有标题和几个关键词。
- 页面太空。
- 小字密密麻麻。
- 没有笔记本材质。
- 红色用得太多，层级混乱。
- 看不出它在讲什么。

## 6. 风格锁检查

多张图必须一致：

- 字体或笔迹。
- 标题层级。
- 标签样式。
- 色彩系统。
- 材质。
- 构图方式。
- 图标或手绘元素风格。

如果某一张明显漂移，要重写 prompt 并重生成。

## 7. 真实性和隐私检查

检查图片是否可能让读者误以为它是真实证据：

- 是否像真实聊天记录。
- 是否像真实支付或转账截图。
- 是否像真实后台数据。
- 是否像真实平台通知。
- 是否像官方认证、奖项或证书。
- 是否出现未经允许的真实品牌、logo 或人物背书。
- 是否出现手机号、微信号、订单号、身份证号等隐私信息。

如果有误导风险，改成示意图、流程图、抽象图、虚构样例或脱敏表达后重生成。

## 8. 交付前检查

展示给用户前再确认：

- 是否展示的是成功版本，不是失败版本。
- 是否简短说明图片用途。
- 是否说明了仍需用户确认的轻微问题。
- 是否没有把内部失败记录、敏感词清单或隐私内容直接暴露给学员。
- 是否需要把稳定偏好写入 `memory.md`。

## 9. 失败记录

失败时记录：

```md
## 尝试 v1

- 状态：失败
- 问题：
- 可能原因：
- 下一版 prompt 修改：
```

同一张图最多重试两次。两次仍失败，就停止并告诉用户下一步建议。
